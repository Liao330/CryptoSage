# 分析报告（ANALYSIS_REPORT）

> 本报告汇总：场景选择理由 → AI 应用解决方案 → 评估维度设计依据 → 评测结论 → 模型失败模式归纳与能力边界 → 实测典型模式。
> 含"待回填"部分表示需在评测实际运行后基于数据补充；推理与设计部分为已完成内容。

---

## 1. 场景选择理由

选择 **金融分析（加密市场研判）开放式场景**，理由：

1. **真实且有需求**：加密货币 7×24 交易、信息源碎片化且充满噪声（技术/链上/衍生品/舆情/宏观互相交织），用户比任何传统市场都更需要"把判断依据摊开看"的工具；
2. **天然无唯一标准答案**：同一时刻的多空判断依赖时效与风险偏好，不存在 benchmark 式标准答案，正符合实战任务一"开放式场景"的定义；
3. **复杂度足够暴露模型边界**：需要长时间推理链、多轮工具调用、时效判断与合规约束，能较好地检验 Hy3 在 Agent/Function Calling/多档思考下的真实能力；
4. **失败代价可管理**：系统明确"不构成投资建议"并将所有方向性研判纳入**影子回测**（不产生真实仓位），适合作为研究学习型开放场景。

## 2. AI 应用解决方案

### 2.1 用户问题到产出的映射

一次典型任务 `POST /api/analyze {symbol, query}` 产出：实时事件流（编排/取证/融合/对抗）→ 最终研判 JSON（方向 + 置信度 + 关键价位 + 风险边界 + 规则化行动建议）→ 可回放报告。

### 2.2 关键设计（为什么这样解决）

| 设计 | 解决的问题 | 与评估的关系 |
|---|---|---|
| 两层 Loop（Orchestrator 编排 + Synthesis↔Critic 对抗） | 单轮问答无法完成"多源取证 + 综合"，且模型容易确认偏误 | D3 评估"推理一致性"的直接对象 |
| 证据驱动的确定性校准（方向/置信度由公式计算，LLM 不自评） | 防止模型自评置信度虚高、防幻觉式"很有把握" | D1/D3；也是 anti-hallucination 工程护栏 |
| 数据质量分级（real/partial/degraded）与少源置信度封顶 | 数据源不可达时的诚实降级 | 反例样本要考的 D1/D4 |
| 新闻时效守卫（滞后 5min 封顶 45%） | 避免用陈旧信息下结论 | 反例样本"陈旧信息" |
| 政府抛售事件链上取证 + 双来源确认 | 对抗"标题党"新闻 | 反例样本"假新闻诱导" |
| 反事实压力测试 / 影子回测校准 | 自证结论敏感度并持续校准各 Agent 权重 | 为 D3 与系统可信度提供旁证 |

## 3. 评估维度设计依据

- **为什么是这 6 个维度**：任务文档建议的通用维度（事实准确性、证据可追溯性、专业术语正确性、安全合规性、用户可理解性、格式规范性）在本系统上逐一映射为可观察对象。D1=事实准确性，D2=证据可追溯性，D3=推理一致性（映射"专业术语正确性"为"概念/术语使用是否正确且与结论自洽"），D4=风险与合规（映射安全合规性），D5=结构化与可读性（映射格式规范性 + 用户可理解性），D6=过程质量（开放场景特有，防止"空转烧步数"）。
- **为什么每个维度要求行为锚点**：评审者（人或 LLM）需要"看什么证据给几分"的确定性指引，行为锚点是让不同评审者结论收敛的前提（详见 `EVALUATION_METHOD.md` 与 `evaluation/rubric.md`）。
- **为什么引入失败模式标签**：把评分从"一个分数"扩展到"一组可解释的失败类型"，使归因和模型边界分析可以量化。

## 5. 模型失败模式归纳与能力边界分析（初版框架 + 待实测验证）

以下基于系统工程护栏与设计预期，罗列**可预期的失败模式**，实际频次与比例由评测数据回填：

| 模式 | 成因假设 | 工程上已设护栏 | 评测观测项 |
|---|---|---|---|
| 编造/歪曲数值（hallucination） | 长链推理丢失数字来源 | 关键价位由算法计算、LLM 仅解释；工具输出进入证据池 | D1、`hallucinated_fact` |
| 单源下结论 | Orchestrator 取证不足即融合 | 单源置信度 ≤54%、数据不足 ≤35% | D2/D4、`single_source` |
| 新闻时效失效 | 宏观事件窗口错配 | 24h 有效窗口 + 5min 滞后守卫 | `stale_news` |
| 中文金融媒体噪声 | 语言区域导致方向误判 | 默认 en-US 新闻区 + 中国财经新闻不参与方向加权 | D1/D3 |
| 舆情极端错用 | 把极端情绪当方向 | 反身性（极端情绪反向） | 反例样本 |
| 结构化输出退化 | 长输出 schema 漂移 | `_stringify_list` 归一化 + 前端兜底 | D5、`schema_error` |
| 空转/不收敛 | 编排步数失控 | 去重 + 早退 + 步数上限兜底 | D6、`empty_flail` |

**能力边界（任务文档要求的"临界点"）**：
- **时效边界**：研判对 ≤24h 宏观事件敏感，超过有效窗口需重新分析；
- **数据源边界**：在数据源不可达时会诚实降级为 `degraded`，此时不应把系统输出当作完整研判（`/api/shadow/stats` 中的 `eligibility_policy`）；
- **合规边界**：系统不做精确价格预测、不给临床式交易指令，默认低置信时仅观望；**任何输出不构成投资建议**；
- **领域边界**：仅覆盖 BTC/ETH 及其衍生品/链上主流信号，不扩展到 altcoin/DeFi 长尾。
